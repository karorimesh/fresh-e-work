Incorrect mobile number format for customer country

Reported by: User reported

Priority: High

What happens

Customer mobile numbers are being stored or processed without applying the correct phone number format for the customer's country.

The current CustomerDTO does not contain a country field, which prevents the Spring Boot service from determining which country-specific mobile number format should be applied.

For example, a customer from South Africa should have their mobile number normalized to the expected South African format, while customers from other countries should follow their respective country's numbering format.

What we expect

The customer's mobile number should be validated and formatted according to the customer's country.

The CustomerDTO should be updated to include a country field, or the service should otherwise have access to the customer's country before processing the mobile number.

The service should then:

Determine the customer's country.
Validate the mobile number against the country's numbering rules.
Normalize/format the number into the expected international format.
Reject invalid mobile numbers with an appropriate validation error.

For example, a South African number such as 0712345678 should be normalized to the appropriate international representation, such as +27712345678.

Notes
The current CustomerDTO does not contain a country field.
Mobile number formatting should not assume a single country or numbering scheme.
Existing customers and API consumers should be considered when introducing the new country field.
The implementation should use a reliable phone-number validation/formatting library rather than country-specific formatting logic hardcoded in the service.
